# Smart Parking Management System

## Analysis of the Client Requirements

The client requires a modern parking management system that automates the main activities involved when a vehicle enters and leaves a parking facility.

The system must allow drivers to see the available parking spaces before entering. When a vehicle arrives, the system should record the vehicle and the time of entry. When the vehicle is ready to leave, the system should determine how long it has been parked and automatically calculate the parking fee. The vehicle should only be allowed to exit after the required parking fee has been paid.

To meet these requirements, the Smart Parking Management System is divided into eight proposed modules. Each module performs a specific function, while all the modules work together as one complete system.

## Proposed System Modules

### 1. Parking Availability and Visual Display Module

This module keeps track of the status of all parking slots. A parking slot can be available or occupied.

Before a driver enters the parking area, the module checks the number of available parking slots and displays this information visually.

For example:

- Total Parking Slots: 10
- Available Slots: 7
- Occupied Slots: 3

The display should be updated whenever a vehicle enters or exits the parking facility.

This module satisfies the client's requirement that drivers should be able to see available parking slots before entry.

---

### 2. Vehicle Entry Module

This module handles vehicles arriving at the parking facility.

The system receives the vehicle registration number and checks whether parking space is available.

If parking space is available, the system records the vehicle registration number and the current date and time.

The system should also prevent the same vehicle from having more than one active parking session.

If there are no available parking spaces, the driver should be informed that the parking facility is full.

---

### 3. Parking Slot Allocation Module

This module assigns an available parking slot to a vehicle that has been allowed to enter.

The system searches for a free parking slot and assigns it to the vehicle.

After allocation, the status of the selected parking slot changes from:

`AVAILABLE`

to:

`OCCUPIED`

The parking availability display is then updated to show the new number of available parking spaces.

---

### 4. Parking Session Management Module

A parking session represents the period between the time a vehicle enters the parking facility and the time it leaves.

The parking session stores important information such as:

- Session ID
- Vehicle registration number
- Allocated parking slot
- Entry time
- Exit time
- Parking status

When a vehicle enters, the session status is recorded as `ACTIVE`.

The exit time remains empty until the vehicle requests to leave.

After the vehicle successfully exits, the session status changes to `COMPLETED`.

---

### 5. Parking Duration Calculation Module

This module calculates the total amount of time a vehicle has spent in the parking facility.

When the vehicle requests to leave, the system retrieves its recorded entry time and compares it with the current exit time.

The difference between the two times gives the total parking duration.

For example:

- Entry Time: 8:15 AM
- Exit Time: 11:05 AM
- Parking Duration: 2 hours and 50 minutes

The calculated parking duration is then passed to the fee calculation module.

---

### 6. Parking Fee and Payment Module

This module calculates the parking fee based on the total parking duration and the parking tariff.

The parking tariff should be stored in the system so that the management can change the parking charges when necessary.

After calculating the fee, the system displays the amount that the driver is required to pay.

The module then records whether payment has been successful or unsuccessful.

The important rule is that a vehicle should not be allowed to leave until payment has been successfully confirmed.

---

### 7. Vehicle Exit and Barrier Control Module

This module controls the final stage of the parking process.

When a vehicle approaches the exit, the system checks whether the vehicle has an active parking session and whether the parking fee has been paid.

If payment has not been completed, the barrier remains closed.

If payment has been successfully confirmed, the barrier changes to an open state and the vehicle is allowed to exit.

After the vehicle leaves:

- The parking session is completed.
- The exit time is recorded.
- The parking slot becomes available again.
- The parking availability display is updated.
- The barrier returns to the closed state.

---

### 8. Database Management Module

This module stores and manages the information generated by the entire parking system.

The database should store information about:

- Vehicles
- Parking slots
- Parking sessions
- Parking tariffs
- Payments

The database is dynamic because the information changes as vehicles enter and leave the parking facility.

For example, when a vehicle enters, its parking slot changes from `AVAILABLE` to `OCCUPIED`.

When the vehicle leaves after payment, the parking session changes from `ACTIVE` to `COMPLETED`, and the parking slot changes back to `AVAILABLE`.

The database therefore supports the other modules by providing permanent and up-to-date information.
